# Feature Parity — DocsGuard vs. the original TradeGuard

Honest gap analysis between the original TradeGuard prototype (extracted, read in full) and the
current DocsGuard codebase. Every claim below is backed by a file + line reference I actually read —
nothing here is guessed. Original files read: `App.tsx` (393 ln), `components/AnalysisResult.tsx`
(673 ln / 42.8KB), `components/DashboardHome.tsx` (611 ln / 32.9KB), `components/LandingPage.tsx`
(493 ln / 29KB), `components/CompanySearch.tsx` (221 ln), `components/AiAssistant.tsx` (133 ln),
`components/FileUpload.tsx` (203 ln), `components/dashboard/{CRMModule,DealsModule,SupplierModule}.tsx`,
`components/ui/{DotShaderBackground,LiquidBackground}.tsx`, `types.ts` (277 ln). Current files read:
`App.tsx`, `pages/*.tsx`, `components/*.tsx`, `components/motifs/Motifs.tsx`, `types.ts`.

## 2. UI richness the original had that we lost (as asked)

Going section-by-section on exactly what "visual richness" meant in the original, and its current status:

- **Animated scanning sequence & its stages** — **present and well-rebuilt.** Both versions show a 4-step timed stepper (icon → checkmark transition, active-step pulse) with a sweeping scan-line across the card. Original: `FileUpload.tsx:62-113` (raw CSS `@keyframes scan`). Current: `components/FileUpload.tsx:79-160` (framer-motion, plus `motion-reduce:hidden` for the sweep — actually more accessible than the original, which ignored `prefers-reduced-motion` entirely). **Not a gap.**
- **Module/tab navigator in the report** — **lost, real gap.** Original had a persistent left rail (`AnalysisResult.tsx:143-177`) listing all 12 modules with icons, letting a reviewer jump straight to "Financial Risk" or "Legal Integrity" and see which module they're currently reading via scroll-spy. Current `DossierSections.tsx` renders modules as an accordion list (`ModuleCard`, `ModulesSection:111-124`) with no jump nav, no active-section indicator, and no way to see all module statuses at a glance without scrolling past everything.
- **Visual density** — mixed. The original's report view was a genuinely dense, information-per-pixel dashboard (dark cards, 2-column grids, inline stat chips everywhere). Current `ResultView.tsx` is airier (more whitespace, single-column stacked sections below the fold) — this is partly a deliberate, correct design-system choice (light "fintech-trust, lots of white space" per `docs/DESIGN_SYSTEM.md`), but it does mean a power user sees less at a glance and scrolls more. Not a bug, but worth knowing it's a trade-off, not an oversight.
- **Background effects** — **lost, and correctly so for the literal effect, but the idea is underused.** `DotShaderBackground.tsx` (indigo dot-wave canvas on black, `mix-blend-screen`) and `LiquidBackground.tsx` (5 drifting blurred blobs, mouse-reactive) ran on every screen in the original. Neither exists today. The current design system explicitly rules out dark backgrounds and asks for "restrained motion," so a literal port is wrong — but the current app also has *zero* ambient motion anywhere except the hero's static `.dotgrid` texture, which is a missed opportunity for a light, subtle equivalent (see §3, item 3).
- **Micro-interactions** — roughly at parity or better. Current uses framer-motion consistently (`whileHover`, `whileTap`, staggered reveals via `containerVariants`/`itemVariants` in `ResultView.tsx:141-149`) versus the original's plain CSS `hover:scale-105` / `animate-in` Tailwind utility classes. The count-up risk ring (`RiskRing`, `ResultView.tsx:191-224`) is a nice addition the original never had (original just printed the number statically inside a div). **Current is ahead here.**
- **Empty states** — at parity or better. Both have a "no scans yet" state; current's (`Dashboard.tsx` `EmptyState`, `Workspace.tsx` sidebar empty state) is arguably clearer because it explains *what will appear* once populated, rather than the original's generic "No audits found in history."
- **The multi-page printable dossier** — **the single biggest concrete gap**, covered in §1 and §3: a full replacement component (`ExportDossier.tsx`) exists and is simply not wired up; `window.print()` on the live page is what ships today.
- **Stat cards** — current is ahead (4 real, code-computed cards vs. original's 2 partly-fabricated ones — see table).
- **Charts** — current is ahead (2 real data-driven charts vs. original's 1 decorative fake map).

## 3. Opinionated take

**Correctly left out — do not rebuild:**
1. **CRM / Deals / Supplier modules.** These are trade-relationship-management features bolted onto a fraud-detection tool. They don't verify anything about a document's authenticity, they duplicate what any real CRM already does far better, and rebuilding them would be pure scope creep that dilutes the product's actual value proposition. If the business genuinely needs contact/deal tracking, that's a separate product decision, not a "parity" item.
2. **CompanySearch's fabricated OSINT** (fake registration numbers, fake WHOIS, fake "key people") and the **fake pricing tiers / fabricated testimonials / non-functional contact form.** All four directly violate this project's own HONESTY_RULE. `EntityIntel.tsx` and `pages/Pricing.tsx` already replaced them with honest, narrower equivalents — that's a fix, not a regression, and re-adding the fabricated versions would be a step backward.
3. **The literal dark-canvas backgrounds** (`DotShaderBackground`, `LiquidBackground`). They actively contradict `docs/DESIGN_SYSTEM.md`'s explicit anti-pattern list. Porting them as-is would be wrong for this product's visual identity.

**Genuinely missing depth — worth restoring, in priority order:**
1. **Wire up `ExportDossier.tsx`.** It's already built, already on-brand, and already more complete than the original's PDF (cover + TOC + one page per module + court page + evidence page + action page). Today it's dead code and the "Download / Print report" button just does a raw `window.print()` of the live scrolling page. This is a near-zero-effort fix relative to its impact.
2. **Report module navigation.** Rebuild a sticky module rail (or at minimum a horizontal jump-nav/progress strip) for `DossierSections.tsx`, mirroring the original's `activeModule` + `scrollIntoView` pattern but styled to the light system — this is what actually made the original report feel "enterprise" rather than a long article.
3. **Dashboard bulk actions**: multi-select + compare-2-reports + CSV export on `/dashboard`'s recent-scans table. Real, non-fabricated workflow value once a user has more than ~10 scans.
4. **A restrained, light-mode ambient effect** — not a literal port, a redesign in spirit: e.g. a very faint animated `.dotgrid` drift (opacity ≤0.05, blue-tinted, `prefers-reduced-motion` gated) behind the Workspace/report shell only, consistent with "Optional texture: `.dotgrid`… Soft blue radial glow" already sanctioned in the design system. Scope this small; the system explicitly asks for restraint.
5. **FAQ accordion** on the landing page, using real, true content (already-true facts about formats/accuracy/data handling) — cheap, honest, and reuses an interaction pattern (expand/collapse) that doesn't need any new component.
6. **Small polish**: session-memory banner on Workspace ("N documents scanned this session"), and (lower priority) a lightweight notification affordance on Dashboard once there's something real to notify about.

## Top 6 gaps (summary)

1. **`ExportDossier.tsx` is fully built (721 lines, cover+TOC+per-module+court+evidence+action pages) but never imported anywhere** — the live "Download / Print report" button just calls `window.print()` on the on-screen page. Cheapest, highest-impact fix in this whole review.
2. **No module/tab navigator in the report view.** The original's sticky sidebar with scroll-spy (`AnalysisResult.tsx:143-177`) is gone; `DossierSections.tsx` is accordion cards in one long scroll with no jump navigation.
3. **No dashboard bulk actions.** Original's multi-select + 2-report compare modal + CSV export (`DashboardHome.tsx:123-339`) has no equivalent on `pages/Dashboard.tsx`'s recent-scans table.
4. **Zero ambient motion anywhere in the app** beyond a static hero dotgrid texture — the original's two canvas backgrounds are correctly dropped as dark-mode-incompatible, but nothing light replaced them.
5. **No FAQ section** on the landing page, despite having entirely honest, non-fabricated content available to put in one (unlike testimonials/blog, which would require fabrication and are correctly left out).
6. **CRM, Deals, and Supplier Watchlist modules are correctly not rebuilt** — flagged here as a deliberate scope decision, not an oversight: they're trade-relationship-management features orthogonal to document-verification, and two of their three data sources (CompanySearch-style AI "auto-enrichment") would violate the project's HONESTY_RULE if resurrected.
